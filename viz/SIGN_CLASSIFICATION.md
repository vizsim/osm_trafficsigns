# Sign classification

Auto-generated by `scripts/extract_sign_colors.py`. **Do not edit by hand** — re-run the script to refresh.

## How it works

Each sign code maps to a `{fill, stroke}` pair (used for the low-zoom dots in `viz/`) and optionally an `svg` basename (used for the high-zoom marker icon). Entries come from three sources:

1. **direct** — there's a matching SVG file in `symbols/DE/`; colors are derived by scanning its `fill:` and `stroke:` attributes, bucketed by hue.
2. **family alias** — e.g. `244` inherits from `244.1` because that's the only `244-*` file. Multi-variant families (`274`, `1000`) get colors but no `svg` — we don't know which specific variant to draw. Exceptions are listed in `PREFERRED_FAMILY_VARIANT` at the top of the script (e.g. `241 → 241-30`).
3. **parquet alias** — codes found in `output/*.parquet` are matched against the table after stripping list separators (`1000-32;206`), country prefixes (`DE:242.1`), and bracket / colon notation (`274[30]`, `274.1:30`, `274:30` → `274-30`). See `src/tsp/signlist.py` for the rules.
4. **manual override** — codes that don't have an SVG but should still render with a recognisable colour (e.g. `310` Ortstafel — yellow with black border). Listed in `MANUAL_COLOR_ENTRIES` at the top of the script. The viewer generates a coloured circle bitmap for these instead of the grey fallback.

Codes the table can't resolve at all (free-text annotations, signs without any SVG in the upstream library) render as **grey fallback dots with the raw code overlaid as a white-box label** in the viewer. Grey is reserved for fallbacks; real yellow/amber signs like the city-limit *Ortstafel* keep their natural colour.
